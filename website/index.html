For devices afterlit check does not find, afterlit uses local Bluetooth captures to infer commands, asks for approval before each probe write and checks the state the device reports back.

Is your device already supported?

Many Bluetooth gadgets already have free, local software from other projects. afterlit check looks for that first, so you only investigate devices that are not already on its list.

This page has no lookup box: afterlit check runs in the afterlit command-line tool, which is not publicly available yet.

You give it the name your device shows in Bluetooth settings, or its brand or model. The lookup runs on your computer against a small built-in list. It does not scan, connect to or write to any device.

  • Already supportedA free project lists support for this device family. afterlit names the project and where to get it, so you can use that instead. afterlit has not tested these projects.
  • Not freed yetNothing on afterlit's small built-in list matches. A free project may still exist; this is where afterlit's contributor tools come in.
  • Out of scopeafterlit will not touch it. This happens when the name contains words such as lock, heat, reset, erase, factory, OTA or DFU (firmware update modes), even inside a longer word, and for some excluded device families. It is cautious on purpose, so some harmless names are refused too.
  • Local recipeOnly when you point afterlit to a folder of recipes you supplied yourself. There is no public recipe library.

afterlit says how sure it is:

"is"
a specific name pattern matched
"is likely"
look-alike devices share that pattern
"may be ... (unconfirmed match)"
only a brand or a loose hint matched

Any match is a lead, not proof that your device will work.

Is your computer ready for Bluetooth?

Before you use a real device, afterlit doctor checks Python, the Bluetooth library and your operating system. Each check has a short code and reports OK, Check, Problem, Skipped or Not applicable, with a one-line fix where there is something to fix.

By default doctor does not use Bluetooth, writes no files and reads no credentials. Add --radio for a three second scan for nearby devices. The scan does not connect, pair, or read or write device data, but like any Bluetooth scan it may send standard scan requests. Your computer may ask for Bluetooth permission.

doctor expects Windows 11 (build 22000 or later), macOS 10.15 or later, or Linux with BlueZ 5.55 or later, and reports Windows 10 as a problem. These minimums come from the Bluetooth library afterlit uses; they are not the result of device testing.

The practice run: afterlit demo

afterlit demo runs the whole process on a simulated lamp. It needs no Bluetooth radio, device, account or cloud service, and saves its files in a new folder each time. You need an authorized copy of the private source to run it.

LOCAL TERMINALNO RADIO REQUIRED
$ uv sync
$ uv run afterlit demo
Practice run on a simulated lamp. No real device was touched and nothing left this computer.
3 of 3 controls confirmed by reading the device's state back.
Home Assistant / MCP / ESPHome outputs are developer drafts, not installable yet.
The key is temporary; the signature checks the receipt and activity log for changes, not who made them.

Notes for developers

The run also lists the controls it learned, prints where its files are saved and shows the temporary key's fingerprint. Developers can still run the detailed afterlit hunt command. Its simulated strip carries a fixed 0xFF filler byte in the power frame, covered by a pre-declared allowance that the signed receipt records; a real device needs that allowance confirmed by hand.

For contributors: how afterlit frees a new device

When afterlit check says "not freed yet", a contributor who owns the device can investigate it. The order is scan, then capture, then hunt. This path is pre-alpha and has not yet passed real-device testing.

01 Capture: observe first.

Record the Bluetooth messages between the vendor app and a device you own, or use the built-in simulated capture.

02 Infer: find the pattern.

afterlit turns the recording into a list of likely commands that you can review.

03 Approve and verify: check the result.

On a real device, afterlit asks before every write. A command counts only when all its checks pass and the device reports the change back.

04 Save: keep the evidence.

afterlit saves a local driver, draft integrations, plain notes about the protocol and a signed record of what was tested.

What a run produces

The prototype emits starting points for local control and a record of what was actually tested. Generated integrations are drafts that need configuration and review.

  • Python driverLocal command encoding and state readback
  • Home Assistant, MCP & ESPHomeIntegration skeletons and drafts
  • PROTOCOL.mdHuman-readable protocol notes
  • Signed receiptIntegrity record for the run and action log

The probe starts read-only. Each write requires a new approval. The probe checks every fixed byte of each command, refuses dangerous command names and known OTA/DFU targets, and never logs the Bluetooth characteristics that identify a device. Notification subscriptions need approval too.

Questions about afterlit

Will this work with any device?

No. afterlit check is the first step: it shows whether a free project already lists support for your device's family. A name match is a lead, not proof of support. For other devices, the real Bluetooth path still needs Gate 1 testing.

Do afterlit check or afterlit doctor touch my device?

Neither connects to, pairs with or writes to a device. afterlit check never uses Bluetooth; it compares the name you give it with a small built-in list. afterlit doctor uses Bluetooth only if you add --radio, and then it only scans for nearby devices for three seconds. Like any Bluetooth scan, that may send standard scan requests, and your computer may ask for Bluetooth permission.

Does it flash firmware?

No. The current project does not flash firmware or bypass authentication, pairing, DRM, or licenses.

What does a receipt prove?

Its signature and hash chain can show that recorded data has not changed since signing. By default each run uses a one-off key; contributors can sign with their own key and verifiers can pin its fingerprint. A receipt does not establish that hardware was present or that an action was safe. Automated registry acceptance is not implemented.

Can I use it today?

Not as a public download yet. afterlit is pre-alpha and its source is private. People with authorized access to the source can look up a device with afterlit check, check their computer's Bluetooth setup with afterlit doctor, and run the offline practice run with afterlit demo. Freeing a real device has not yet passed hardware testing (Gate 1); real-device writes each need your approval, and generated integrations are drafts.

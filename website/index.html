What you can do today

If your device's app or cloud service has stopped working, afterlit cannot help you directly yet. These three steps are worth doing in the meantime.

  1. 01 Search for a free project.Search the web for your device's name, as it appears in Bluetooth settings or on the box, together with "Home Assistant" or "open source". Many Bluetooth gadgets already have free, local software from other projects. Check that the project names your exact model, and follow its own instructions. afterlit has not tested these projects.
  2. 02 Keep the vendor app and the pairing.Leave the vendor app installed and the device paired with your phone. To investigate a device, a contributor records the Bluetooth messages between the vendor app and that device, so the app is worth keeping even if its cloud features have stopped.
  3. 03 Check back later.There is nothing to download or sign up for yet. The status table further down this page lists what is available, what is pending and what is not built yet.

Useful hardware shouldn't expire with a server.

If afterlit check finds no free project, a contributor can use afterlit to study local Bluetooth recordings and find likely commands. It asks before sending each test command (a probe write), then checks the state the device reports back (readback).

Is your device already supported?

Many Bluetooth gadgets already have free, local software from other projects. afterlit check looks for that first, so you only investigate devices that are not already on its list.

This page has no lookup box: afterlit check is part of afterlit's command-line tool, which is not public yet.

You give it the name your device shows in Bluetooth settings, or its brand or model. The lookup runs on your computer against a small built-in list. It does not scan, connect to or write to any device.

  • Already supportedA free project lists support for this device family. afterlit names it and where to get it. afterlit does not run or test these independent projects.
  • Not freed yetafterlit calls a device "freed" when free, local software can control it. "Not freed yet" means nothing on afterlit's small built-in list matches. A free project may still exist elsewhere; this is where the contributor tools come in.
  • Out of scopeafterlit will not touch it. This happens when the name contains words such as lock, heat, reset, erase, factory, OTA or DFU (firmware update modes), even inside a longer word, and for some excluded device families. It is cautious on purpose, so some harmless names are refused too.
  • Local recipeOnly when you point afterlit to a folder of recipes you supplied yourself. There is no public recipe library.

afterlit says how sure it is:

"is"
a specific name pattern matched
"is likely"
look-alike devices share that pattern
"may be ... (unconfirmed match)"
only a brand or a loose hint matched

Any match is a lead, not proof that your device will work.

Is your computer ready for Bluetooth?

Before you use a real device, afterlit doctor checks Python, the Bluetooth library and your operating system. Each check is one line of its report: a state, then a short code naming the check (AFL-D001 to AFL-D009), then a one-line result, with a fix where needed.

OK
the check passed
Check
worth reviewing before you use Bluetooth
Problem
needs fixing first; Windows 10, for example, is reported as a problem
Skipped
not tested this time: Bluetooth permission cannot be checked without a prompt, and the adapter is tested only with --radio
Not applicable
does not apply to your operating system

Any Check, Problem or Skipped line means your computer is not yet confirmed ready.

By default it does not use Bluetooth, writes no files and reads no credentials.

Radio scan and system requirements

Add --radio for a three second scan for nearby devices. It does not connect, pair, or read or write device data, but like any Bluetooth scan it may send standard scan requests, and your computer may ask for Bluetooth permission.

doctor expects Windows 11 (build 22000 or later), macOS 10.15 or later, or Linux with BlueZ 5.55 or later (BlueZ is Linux's Bluetooth system), and reports Windows 10 as a problem. These minimums come from the Bluetooth library afterlit uses, not from device testing.

The practice run: afterlit demo

afterlit demo is a practice run of the whole process on a simulated lamp, inside the command-line tool. It needs no Bluetooth radio, device, account or cloud service, and saves its files in a new folder each time. It runs only from an authorized copy of the source.

LOCAL TERMINALNO RADIO REQUIRED
$ uv sync
$ uv run afterlit demo
Practice run on a simulated lamp. No real device was touched and nothing left this computer.
3 of 3 controls confirmed by reading the device's state back.
Home Assistant / MCP / ESPHome outputs are developer drafts, not installable yet.
The key is temporary; the signature checks the receipt and activity log for changes, not who made them.

Expected today: exit code 0. Output shortened. In this output, "the device's state" means the simulated lamp's state; nothing real was read. uv sync installs what afterlit needs. MCP lets AI assistants use tools; ESPHome is firmware for small Wi-Fi boards. The signature shows whether the files changed after the run, not who ran it or whether a real device was used.

Notes for developers

The run also lists the controls it learned, prints where its files are saved and shows the temporary key's fingerprint. Developers can still run the detailed afterlit hunt command. Its simulated strip carries a fixed 0xFF filler byte in the power frame, covered by a pre-declared allowance that the signed receipt records; a real device needs that allowance confirmed by hand.

For contributors: investigating a new device

When afterlit check says "not freed yet" (nothing on its built-in list matches), a contributor who owns the device can investigate it. afterlit scan finds the device and checks the list again, afterlit capture records it (step 1) and afterlit hunt does steps 2 to 4. This path has not yet passed real-device testing (Gate 1).

01 Capture: observe first.

With afterlit capture, record the Bluetooth messages between the vendor app and a device you own, or use the built-in simulated capture.

02 Infer: find the pattern.

afterlit hunt turns the recording into a list of likely commands that you can review.

03 Approve and verify: check the result.

On a real device, afterlit asks before every write. A command counts only when all its checks pass and the device reports the change back.

04 Save: keep the evidence.

afterlit saves a local driver, draft integrations, plain notes about the protocol and a signed record of what was tested.

About step 03: the probe starts read-only. Each write requires a new approval. The probe checks every fixed byte of each command, refuses dangerous command names and known OTA/DFU targets, and never logs the Bluetooth characteristics that identify a device. Notification subscriptions need approval too.

The prototype emits starting points for local control and a record of what was actually tested. Generated integrations are drafts that need configuration and review.

Questions about afterlit

My device's app just stopped working. What now?

Start with What you can do today: search the web for your device's name together with "Home Assistant" or "open source", and keep the vendor app installed and the device paired. afterlit itself cannot help directly yet.

Will this work with any device?

No. afterlit check is the first step: it shows whether a free project already lists support for your device's family. A name match is a lead, not proof. For other devices, the real Bluetooth path has not yet passed Gate 1.

Do afterlit check or afterlit doctor touch my device?

Neither connects to, pairs with or writes to a device. afterlit check never uses Bluetooth; it compares the name you give it with a small built-in list. afterlit doctor uses Bluetooth only with --radio, for a three second scan that, like any Bluetooth scan, may send standard scan requests.

Does it flash firmware?

No. The current project does not flash firmware or bypass authentication, pairing, DRM, or licenses.

What does a receipt prove?

Its signature and hash chain (each log entry is linked to the one before, so a change shows) show whether recorded data changed after signing. Each run uses a one-off key by default; contributors can sign with their own key and verifiers can pin its fingerprint. A receipt does not prove that hardware was present or that an action was safe. Automated registry acceptance is not implemented.

Can I use it today?

Not yet. Current status shows which parts exist today. Anyone can try the lamp preview on this page; it is only an illustration and connects to no device. Real-device control has not passed Gate 1, every real-device write needs your approval, and generated integrations are drafts.
